# 消息图谱 Message Atlas

消息图谱是一款本地优先的 Android 通知聚合与 AI 重点整理应用。它通过系统通知使用权自动记录各应用的新通知，并在用户主动操作时，将指定日期的消息交给用户配置的 AI 接口整理成清晰的重点卡片。

> 当前版本：`v0.3.3` 测试版。最低支持 Android 8.0（API 26），目标 Android 15。

## 下载与体验

请在仓库右侧 **Releases** 中下载最新的 `message-atlas-v0.3.3-optimized.apk`。这是启用 R8 和 release 级优化、使用 Android Debug 证书签名的体验版本，适合安装测试；正式商店发布版本将使用独立发行签名。

安装后首次打开应用，按引导进入系统页面开启“通知使用权”。通知抓取能力建议使用真机测试。

## 核心能力

- 自动记录通知标题、正文、时间、来源应用及原始状态
- **AI 智能巡检**：支持自定义检查频率（5–720 分钟，默认 10 分钟），自动将新增消息交给 AI 研判紧急程度，发现重要紧急事项立即触发高优先级强提醒（横幅、强震动、提示音，可分别开关），无需手动打开应用
- **人物消息即时强提醒**：归档通知后本地即时识别人际对话，优先提醒别人发来的消息；使用驻留通知、声音与震动渠道增强可见性，点击进入应用后清除
- **低耗电后台设计**：不新增前台常驻服务、不增加轮询、不逐条调用 AI；强提醒在通知归档链路内完成，减少后台唤醒、内存和网络开销
- **自动检查更新**：每 24 小时静默检查 GitHub 最新发布（可关闭），发现新版本后可在应用内一键下载并拉起安装，设置页支持手动检查
- 按日期浏览，支持搜索、来源筛选、重点标记和删除
- 全部收录、白名单、黑名单三种规则模式
- 自定义 OpenAI Chat Completions 兼容接口、密钥和 Prompt
- 通过兼容接口的 `GET /models` 自动获取提供方模型列表，同时允许手动输入模型 ID
- AI 输出严格结构化 JSON，应用原生展示“立即关注、待办、重要、一般、次要”卡片
- API 密钥使用 Android Keystore AES-GCM 加密，仅保存在本机
- Compose 原生页面滑动动画，由 Android 帧时钟跟随设备刷新节奏绘制，并支持关闭动画
- 明暗双主题自适应：跟随系统深色模式，卡片、语义色与状态指示全部联动
- AI 日报本地存档、收藏、删除和纯文本分享

## AI 接口兼容说明

填写 Base URL，例如：

```text
https://api.example.com/v1
```

应用会调用：

```text
GET  /v1/models
POST /v1/chat/completions
```

模型提供方需要返回 OpenAI 兼容的模型列表和 Chat Completions 响应。若提供方没有 `/models` 接口，仍可直接在模型输入框填写模型 ID。Anthropic、Gemini 等原生协议暂未直接适配，可使用兼容网关。

## 隐私与权限

Manifest 仅声明网络、通知发布、震动、唤醒与精确闹钟（仅 Android 12/12L）权限。通知读取由 Android 专用设置页授权，应用不申请通讯录、短信、相册、定位或“查询全部应用”权限。

- 浏览、筛选与本地归档完全离线
- 生成 AI 报告时发送当天消息；开启“AI 智能巡检”后，每 10 分钟将新增消息发送到你配置的接口进行紧急程度研判，可随时关闭
- 密钥不会写入日志或上传到本项目服务器
- 为兼容可信局域网私有模型，测试版允许 HTTP 明文接口；公网接口应使用 HTTPS

## 本地构建

环境要求：Android Studio、JDK 17、Android SDK Platform 35。

```powershell
$env:JAVA_HOME='你的 JDK 17 路径'
./gradlew.bat assembleDebug
```

生成文件：

```text
app/build/outputs/apk/debug/app-debug.apk
```

## 部署与安装

1. 在 Android Studio 中打开本仓库，等待 Gradle 同步完成，并确认已安装 JDK 17、Android SDK Platform 35。
2. 连接一台 Android 8.0（API 26）或更高版本的测试设备，开启 USB 调试；也可以启动 Android Studio 模拟器。
3. 在项目根目录执行 `./gradlew.bat assembleDebug`，构建完成后使用 `app/build/outputs/apk/debug/app-debug.apk` 安装到设备。
4. 首次启动应用后，按照引导打开系统的“通知使用权”；如需 AI 巡检，再在设置中填写兼容接口的 Base URL、模型 ID 和 API 密钥。
5. 如需直接体验已构建版本，从仓库 Releases 下载最新 APK，安装后同样完成通知使用权授权。

卸载或清除应用数据会删除本机保存的通知、报告和设置；应用不会把 API 密钥上传到本项目服务器。

## 已知边界

- Android 各厂商后台策略不同，无法绝对保证进程永不被系统限制；通知监听服务由系统绑定，配合电池优化与自启动设置可降低漏录概率。
- 通知内容由发送方决定，部分应用可能只提供摘要、隐藏敏感内容或使用自定义布局。
- 超大量通知尚未加入分批摘要和 token 预算策略。
- 当前为 Debug 测试包，正式发布前还需发行签名、数据库迁移测试、OEM 机型测试、隐私政策和商店素材。

## 版本变化

### v0.3.3

- **修复人物提醒未触发**：为微信、QQ、钉钉、飞书、Telegram、WhatsApp、Discord、Teams 和短信增加本地兜底识别，不再完全依赖发送应用提供标准对话元数据
- **全新强提醒渠道**：使用新的高重要性通知渠道，默认启用系统铃声、三段长震动、灯光、公开锁屏与横幅资格，避免旧渠道的静默设置继续生效
- **每条人物消息重新提醒**：新消息到达时替换旧的驻留提醒，避免 Android 将相同通知 ID 视为无声更新
- **独立于 AI 设置**：人物消息强提醒固定启用响铃和震动，不受 AI 巡检的响铃/震动开关影响；设置页测试按钮改为直接测试人物强提醒真实链路
- Android 仍会尊重用户关闭通知/渠道、勿扰模式和厂商系统策略，应用不能绕过这些系统级限制

### v0.3.2

- **人物消息即时强提醒**：本地识别通知中的人物对话，优先处理别人发来的消息，不等待 AI 巡检
- **驻留与多通道提醒**：人物消息使用驻留通知，并按声音、震动、静默分别使用通知渠道；点击进入应用后清除驻留状态
- **低耗电与低内存**：沿用现有通知监听链路，不新增前台服务、轮询或逐条 AI 请求，尽量降低长期后台运行成本
- **系统限制说明**：响铃、锁屏显示和驻留效果仍受系统通知权限、通知渠道设置、勿扰模式、锁屏策略及厂商省电策略影响

### v0.3.1

- **自定义巡检频率**：设置页新增「检查频率」入口，支持 5/10/15/30/60 分钟预设与 1–720 分钟任意自定义间隔，首页与守护卡文案联动，修改后立即重新调度系统闹钟
- **自动检查更新**：接入 GitHub Releases，每 24 小时静默检查新版本（可在设置中关闭）；发现新版本时首页横幅提醒，支持应用内下载（带进度）并自动拉起系统安装器，亦可手动检查更新

### v0.3.0

- **新增 AI 10分钟智能巡检与强提醒**：后台双轨保活调度（Listener Loop + AlarmManager 息屏精确唤醒），每 10 分钟自动提取新增通知提交 AI 研判。
- **高优先级强提醒系统**：判定为重要紧急事件时自动触发三段式强震动、锁屏全显横幅警报并自动打标星重点；支持一键真机测试。

  - 现代化 7 日水平滑动日历 Carousel 替代传统翻页按钮。
  - 品牌专属色自适应应用头像（微信绿、钉钉蓝、支付宝蓝、美团黄等主流匹配 + 莫兰迪哈希自适应）。
